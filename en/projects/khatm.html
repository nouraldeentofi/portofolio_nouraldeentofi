Khatm · ختم

Open-source e-invoicing for businesses in Saudi Arabia

E-invoicing platform · open source2026

An open-source e-invoicing program for businesses in Saudi Arabia, with a public demo that issues and signs invoices entirely in the browser.

Visit live site (opens in a new tab)

The problem

E-invoicing in the Kingdom's integration phase asks for more than a printed PDF: every invoice is a signed electronic file with a QR code, numbered in an unbroken chain and never edited once issued. Corrections go through credit and debit notes. The hashing and signing must match the official reference exactly.

What I built

A TypeScript monorepo in three parts. An invoicing library builds UBL invoices, hashes them over canonical XML, signs them with ECDSA, generates the QR code and the device's certificate request, and handles onboarding and submission through the official API. A PostgreSQL schema adds guards at the database level: triggers stop an issued invoice from being edited or deleted, stop the counter from going back or skipping, and protect the audit log. The issuing core locks the device row for the whole transaction, so invoices issued in parallel keep an unbroken count and hash chain. Device keys and secrets are encrypted with AES-GCM under a master key kept outside the database, and amounts are calculated in exact decimals. The public demo runs the same library in the browser without changing a line: the seller's invoices grouped by customer, tax invoices for businesses and simplified invoices for individuals, credit and debit notes from an invoice's page, printing to PDF, sending over WhatsApp, and the signed XML file for the accountant. It signs with a public test certificate, sends nothing anywhere, and keeps everything in the visitor's browser; end-to-end tests issue every document type in a real browser and pass each through the official validator.
