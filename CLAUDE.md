# Working in this repository

A bilingual static portfolio. Read `README.md` first for the run commands.

## The one rule

**Never edit `*.html`, `en/*.html`, `projects/`, `automation/`, `en/projects/`,
`en/automation/`, `cv/`, `resume/`, `profile/`, `llms*.txt`, `sitemap.xml`, or
`api/*.json` by hand.**
They are generated by `scripts/build.mjs` and your changes will be destroyed on the next
build. Edit `data/` instead, then run `npm run build`.

`projects/` and `automation/` (and their twins under `en/`) hold one page for each
project and each automation system, `<id>.html`. The build writes them from
`data/projects.json` and `data/workflows.json` and deletes the page of an entry that
has left the data, so nothing else may live in those four folders.

The same goes for `sites/`, `gallery/`, `motion-studio/` and `umrah-guide/`: they are
copies of other repositories made by `npm run sites` (`data/hosting.json`). Change a
client site in its own repository, then re-run the sync.

A copy is not a byte-for-byte copy. The sync (`transformFile` in `scripts/lib/hosting.mjs`)
changes what a crawler reads: it writes the copy's indexing decision into the head of
every page, gives canonicals, hreflang, `og:url`, JSON-LD and nested sitemaps the clean
addresses the host serves, removes rating markup from JSON-LD, and leaves behind test
pages and nested `robots.txt` files. One change a visitor does see: a link, or a link
text, that names a former host is moved to the domain. Nothing else a visitor reads or
uses is touched, in the text, in a form field or in a script.
A rule about the copies therefore belongs in that file, never in a hand edit of a copy.

The CV (`assets/cv/Nour_Aldeen_Tofi.pdf`) is printed from `scripts/cv/cv.html` by
`npm run cv`. Change the HTML and print again; never edit the PDF itself, which leaves
the new text out of reading order for applicant tracking systems. The CV is the one
document that carries its own wording and figures instead of reading them from `data/`.

The share card (`assets/img/og.png`) is photographed from `scripts/og/og.html` by
`npm run og`. Its words are placeholders that `scripts/lib/og.mjs` fills from
`data/profile.json`, so change the HTML or the data and run it again; never edit or
re-export the PNG by hand, which is how the old card kept a title he had dropped. Keep the
file name: every page names that address.

`scripts/lastmod.json` is written by the build as well: a hash of what each page says and
the day that hash was first seen, which is where the sitemap's `<lastmod>` comes from
(`scripts/lib/lastmod.mjs`). Commit it with the pages and never edit it. `validate` fails
when it and the pages disagree.

## Where facts live

Every fact appears in `data/` exactly once:

| File | Holds |
|---|---|
| `data/profile.json` | Identity, contact, the `sameAs` link graph, availability |
| `data/experience.json` | Employment, newest first; roles at one employer stay adjacent |
| `data/projects.json` | Products and applications; `headline` is the search line of its page, `workflow` names the n8n workflow that is its engine |
| `data/workflows.json` | n8n automation systems: status, audience, curated flow, canvas screenshot, `headline` |
| `data/showcase.json` | Client websites (with the owner's permission) and the design lab |
| `data/hosting.json` | Which repository and branch each site on the domain is copied from, whether search engines may list it (`index`), and the hosts the portfolio used to live on |
| `data/credentials.json` | Certifications, education, awards |
| `data/testimonials.json` | Recommendations |
| `data/skills.json` | Skills by category |
| `data/copy/{en,ar}.json` | All prose, both languages, identical key sets |

Three things in `data/profile.json` that are easy to get wrong:

- `updated` is the day his identity facts last changed (name, title, links, portrait,
  location). It is set **by hand** and is the `dateModified` of the ProfilePage on the
  home page. Change it only when one of those facts changes, never because of a rebuild.
- `nameVariants` holds real spellings only, and a handle only if a profile in `sameAs`
  uses it. Every one of them is shown in the name question on the about page.
- The misspelled family name lives in `nameMisspellings` and **nowhere else** in `data/`.
  It ships in one place: `alternateName` of the Person node on the home and about pages.

## Content rules, enforced by tests

These are not style preferences — `npm test` and `npm run validate` fail on them:

- The product is **Smart Scanner**, never "Receipt Scanner".
- **Alessa Group must not appear anywhere.** Smart Scanner is presented as Nour's own
  product work with no employer named.
- His base is **Al Khobar**, never Riyadh. (Khwarizm Technologies was Riyadh-remote —
  that one is correct as written.)
- Arabic and English copy must expose **identical key sets** and equal array lengths.
- Unknown facts are `null` with a sibling `todo` string. They must never render as a link.
- **ZATCA must not appear anywhere**, and the scraper's crawl mode is never tied to the
  site it was built against.
- A workflow `status` is a claim: `client` (running for a real client), `live`, or `built`.
  Diagrams in `flow` are curated from the real n8n node graph — no IDs, prompts or client data.
- **A page of its own** (`/projects/<id>`, `/automation/<id>`) goes to every project, and
  to every workflow that has both a `flow` and a `canvas`, unless a project names it as its
  `workflow`: that one is shown on the project's page instead. `scripts/lib/details.mjs`
  decides, and everything that lists or links asks it. No two pages may share a title or a
  description, and a product name is never translated: not in a heading, and not in the
  copy either. Wherever the English of a pair names a product, the Arabic names it by the
  same Latin letters, the engine of a product included ("وكلاء CV Screener").
- **The card of a project on `/projects` is a summary**: what it is, his role, the figures,
  the stack and the way to its page. The problem, what he built and the context are told
  on `/projects/<id>` only, and a test fails when they are back on the list. The cards of
  the automation page and the featured card on the home page keep their full text: a
  system page already adds the steps, the canvas and the outcome.
- **A detail title is at most eighty characters.** A `headline` does not repeat what the
  name already says, so `<name>: <headline>` stays near seventy; a test holds the bound.
- **A share image is a PNG or a JPEG.** Some link previews do not unfold WebP, so a
  detail page whose screenshot or canvas is a WebP file is shared with the site's card
  (`detailImage` in `scripts/lib/details.mjs`). The `image` of its `CreativeWork` node
  stays the real screenshot or canvas.
- A project or system page is a `CreativeWork` in the structured data, never a
  `SoftwareApplication`: Google wants a price and a rating for that, and neither is invented.
- He is the `author` of what he built. A product he coordinated while others wrote the
  code carries `"credit": "contributor"` in `data/projects.json` (GoldenTag today), and
  its node then names him as `contributor`: the markup claims no more than the role the
  page prints. A test lists the entries that carry it.
- Prose contains **no figures** — every number comes from `data/` so it cannot drift.
- **No em dashes** (`—`) anywhere a reader or a crawler looks: prose, titles, alt text,
  JSON-LD, llms files. Use a comma, colon, full stop or words ("2025 to 2026").
  `validate` fails on any it finds outside inline code comments.
- The same goes for the public files written by hand, `robots.txt`, `humans.txt` and
  `mcp/README.md`: `validate` reads them for em dashes as it reads the pages.
- **Structured data says only what its page shows.** The Person node is slim on every page
  (name, title, address, portrait, profiles) and a page adds only what a visitor can read
  there: the phone number on contact, the certificates on experience, the skills on about
  (`PERSON_ON_PAGE` in `scripts/lib/jsonld.mjs`). His title and address stay in the slim
  node on every page, printed there or not: they are what makes it one identity. A test
  reads each page for every value a page adds, what he is looking for included, which is
  on the contact page only.
- **A picture has one address.** Nothing under `assets/img/` is ever linked with a `?v=`
  fingerprint, in an `<img>`, in `og:image` or in JSON-LD; `validate` fails on one.
  Stylesheets, scripts and the CV keep their fingerprints.
- Alt text describes the picture. A screenshot of someone else's site does not carry
  Nour's name (`shotAlt` in `scripts/lib/blocks.mjs`).
- Every page meant for search carries exactly one robots meta, which allows a large image
  preview. The 404 pages carry `noindex, follow` instead, and no canonical, no hreflang
  and no `og:url`: they have no address of their own.
- A page is called by **one name**: its label in `nav` in the copy. Breadcrumbs and the
  line above a heading read it from there. `navShort` is the phone tab bar: the same word
  or a shorter form of it, never longer than "Projects".
- A showcase tag is one string when it names a technology, and an `{ en, ar }` pair when it
  is plain language ("Dark mode"), so the Arabic page prints no English that is not a name.
- **Every copy of another site has an indexing decision.** `index` in `data/hosting.json`
  is required: `true` (meant to be found here, the client's own robots tags stand), `false`
  (every page carries noindex: `noindex, follow`, or `noindex, nofollow` where the owner's
  page already said nofollow or none, so a copy is never left more open than its
  repository asked) or `"root-only"` (only the entry page is listed, as for the gallery).
  Loading the data fails on an entry without one. Set `true` only when the client wants to
  be found on Google at this address; a `todo` beside it says when that is still to be
  confirmed. The main sitemap lists the entry address of each copy that is not `false`
  and carries no `todo`, with no hreflang and no date: a copy still to be confirmed stays
  as indexable as its repository left it, and is not submitted.
- **A copy that asked AI crawlers to stay out is closed to them at the root.** A
  `robots.txt` inside a folder has no force and the sync leaves it behind, so the wish of
  such a repository is written as `"aiCrawlers": false` on its entry (only beside
  `index: false`), and `robots.txt` at the root then closes that folder in every group
  that names a crawler of an AI company, with its `Disallow` lines above `Allow: /` for
  the parsers that obey the first line that matches. The group for every crawler, and any group for
  a search engine, closes nothing: a page a search engine may not fetch cannot show it
  the noindex that keeps the page out of search. `validate` holds `robots.txt` to the
  data in both directions (`robotsProblems` in `scripts/lib/gates.mjs`).
- **A copy lives in a folder of its own.** The sync replaces the whole folder a `path`
  names, so loading the data fails on a `path` that is not `sites/<name>` or one plain
  folder name, that the main site owns, or that another entry has or contains, and on a
  `dir` that leaves the repository. Nothing may stand under `sites/` without an entry.
  A sync that is stopped half way can leave `<path>.sync` or `<path>.old` beside a copy:
  git ignores both, `validate` fails while one is there, and the next `npm run sites`
  for that copy that gets past the clone clears it.
- `validate` holds every copy to its decision and to the sync: noindex in the head where
  the data says so, the copy's own clean address as the canonical of an entry page meant
  to be found, no canonical, hreflang, `og:url` or sitemap entry ending in `.html`, no
  link to a former host, no folder under `sites/` without an entry, and **no rating
  markup** (`aggregateRating`, `review`): a rating on this domain must come from its own
  visitors. A robots meta or a canonical counts only in the head of a page.
  A failure there means run `npm run sites`, or fix the page in its own repository.

## Code conventions

- ES modules everywhere. Node's built-in test runner only (`node --test`); no framework.
- CSS uses **logical properties** (`margin-inline`, `inset-inline-start`) so the Arabic
  RTL mirror needs almost no overrides. Never write `left:` or `right:`.
- `scripts/lib/*.mjs` are pure transforms — data in, string or object out. Keep them
  side-effect free so they stay unit-testable.
- `scripts/lib/offers.mjs` ties what he offers to where it leads: each offer on the home
  page to its page, each service on the automation page to the systems behind it. Pages,
  JSON-LD and the llms files all ask it, so they cannot disagree.
- `scripts/lib/gates.mjs` holds the checks `validate` runs on what is written by hand
  (`_redirects`, `_headers`, the misspelled name, em dashes, a fingerprint on an image)
  and on what the build writes (an address relative to the page, the canonical and the
  robots meta of a page, the sitemap against the pages and against `scripts/lastmod.json`).
  They are pure, so the tests feed them broken input to prove each one fails.
- A new top-level file or folder that is **not part of the site** needs an entry in
  `PRIVATE_PATHS` in `scripts/lib/gates.mjs` and a rule in `_redirects`; one that is part
  of the site is added to the list in the root allowlist test (`tests/identity.test.mjs`).
  That test fails on anything tracked at the root that is neither.
- `mcp/tools.js` is pure; `mcp/server.js` is protocol wiring only. Do not mix them.
- `assets/js/chat/engine.js` knows nothing about Nour; `script.*.js` knows nothing about
  rendering.
- Pages are named by their **clean address** (`/en/about`, `/en/`), never `about.html`:
  the host redirects the `.html` form. Build every link, canonical and structured-data
  URL with `pagePath()` from `scripts/lib/sitemap.mjs`; `validate` fails on an `.html` one.
- Every address a page names **starts at the site root** (`/assets/...`, `/en/projects`),
  never relative to the page: a page one level down and the 404 page would resolve it
  somewhere else. `validate` fails on a relative `href` or `src`.
- `hreflang="x-default"` is the **English** version of every page, in the head and in the
  sitemap (`X_DEFAULT` in `scripts/lib/sitemap.mjs`). The root address still serves Arabic.
- The build reads the clock in one place (`buildStamp` in `scripts/build.mjs`), and that
  day reaches the output only as the year in the footer and as the date of a page whose
  content changed. Built again on another day from the same data, every file is the same.
- **No JavaScript may render user-facing content.** Everything must be in the HTML
  before scripts run — that is the entire premise of this rebuild.

## Before committing

```bash
npm run check    # test → build → validate
```

`validate` exits non-zero on errors. Warnings about pending GitHub/FIDE/portrait links
are expected until those are supplied.
